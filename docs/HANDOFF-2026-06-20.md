## 1. System architecture (helicopter view)

```
                  Browser (React 19 client components)
                         │
        ┌────────────────┴───────────────────┐
        │                                     │
   BFF proxy routes                    React Server Components
   app/api/*  (Next.js)                (render server-side)
   - reads refresh_token cookie        - lib/api/* SDK
   - mints access token                - getAccessToken() mints token
   - forwards Bearer                     from cookie
        │                                     │
        └────────────────┬────────────────────┘
                         │  Bearer JWT (Authorization header)
                         ▼
              NestJS backend  (http://localhost:8080, NO /api prefix)
              ValidationPipe(whitelist,transform) · CORS allow :3000
                         ▼
              TypeORM · synchronize:true (NO migrations) · Postgres :5434
```

**Backend** — modules: Auth, Users, Content, Pelayan, Reports, Members, Uploads.
Config from `config.yaml` (NOT `.env`). No global route prefix (FE proxies paths 1:1).
JWT carries only `{sub, email}` — no role claim. `synchronize:true`, no migrations.

**Frontend** — route groups `(auth)` / `(content)` public / `(dashboard)` gated CMS.
**Critical architectural quirk:** FE talks to BE via **two inconsistent paths** —
BFF proxy (`app/api/*`) for content writes/reports/members/upload, and a direct
server-only SDK (`lib/api/*`) for pelayan + content reads. This split is the root of
several findings below and the biggest fragility in the system.

## 3. What shipped on `fix/content-author-leak`

### F1 — password-hash leak (Critical) + F5 — authorName

**Problem:** `GET /content/:id` and the *unauthenticated* `GET /content/public/slug/:slug`
loaded `relations:["author"]` and returned the **full `User` entity** (incl. bcrypt
`password`, email, role) to any caller. Separately, the FE expected a flat `authorName`
that the BE never produced (always `undefined`).

**Approach (user-chosen):** defense-in-depth = projection + `@Exclude` global net; nested
author object; public endpoints expose `{name, avatar}`, authenticated expose
`{name, email, avatar, role}` — never `password`.

**Backend changes:**
- `src/content/content.service.ts` — author is now projected, never the raw entity.
  - `findBySlug` / `findPublic` (public) → `{name, avatar}`
  - `findById` / `findAll` (auth) → `{name, email, avatar, role}`
  - Split private `findEntityById` (raw entity) so `update`/`delete` still persist correctly.
  - `create`/`update` reload via `findById` so their responses also carry `author`.
  - List endpoints now `leftJoinAndSelect` author (fixes F5).
  - New exported types: `PublicAuthor`, `PrivateAuthor`, `ContentResponse`.
- `src/users/entities/user.entity.ts` — `@Exclude()` on `password` (global net).
- `src/main.ts` — registered `ClassSerializerInterceptor` globally.
- `src/content/content.service.spec.ts` — **new**; asserts no password leak + correct
  per-visibility shapes. TDD: written red first, then green.

**Frontend changes:**
- `lib/types/content.ts` — `authorName: string` → `author: ContentAuthor | null` on
  `Content` and `ContentListItem`; new `ContentAuthor` type.
- 6 usages migrated to `author?.name`: `content-table.tsx`, `featured-reading.tsx`,
  `news-list.tsx`, `news/page.tsx`, `sermons/page.tsx`, `article-reader.tsx`
  (`authorInitials` made nullable-safe).

**Verification:** BE `npx jest` → 4/4 pass. BE `tsc --noEmit` → clean. FE `tsc --noEmit` → clean.

**Known expected behavior:** `avatar` is `null` until a Google-authed user exists — the
seed/password users never set it (only `createGoogleUser` does), and Google login is off
by default (`google.clientId` empty). This is F8 territory, not a regression.

## 4. Roadmap — what to do next (priority order)

1. **F4 — secrets in git.** Rotate JWT secret + DB password, move to env/secret manager,
   remove `config.yaml` from history. Do before any non-local deploy.
2. **F2 — authorization.** Add a `RolesGuard` + `@Roles()` and put the role into the JWT
   claim (currently only `{sub,email}`). Today any authenticated `viewer` can mutate
   everything; FE UI gating is the only barrier and is bypassable.
3. **F3 / F9 — enum reconciliation.** Decide one source of truth for content `type`
   (`news`/`renungan` vs FE `article|sermon|…`) and user `role` (`editor` missing from FE).
   Consider real DB enums.
4. **F6 / F7 — pelayan query filters.** Implement `month` / `serviceId` filtering BE-side
   (FE already sends them; BE ignores → full-table over-fetch).
5. **F8 — avatar in auth responses;** then cleanup tier F10–F16 + internal smells + stale docs.

## 5. Gotchas for the next dev

- BE `synchronize:true` auto-syncs schema from entities — no migrations. Don't rely on it
  for prod; the entity/DB naming has drift (`content.bodyHtml` is camelCase, rest snake_case).
- No global `/api` prefix — don't add `setGlobalPrefix('api')` without updating FE proxy paths.
- Global `ValidationPipe({whitelist})` silently strips unknown fields — masks contract drift.
- BE e2e suite (`test/app.e2e-spec.ts`) is broken (expects a non-existent `AppController`).
  Only the new `content.service.spec.ts` unit test is meaningful right now.
- FE `.catch(()=>[])` everywhere shows empty states instead of errors — during integration
  testing a field mismatch looks like "no data", not a failure. Watch for it.
- Nothing is merged. This work is on `fix/content-author-leak` in both repos.
